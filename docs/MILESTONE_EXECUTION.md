# Tidelight milestone execution

This document is the implementation contract for the six build stages.

## 1. Evidence workflow

- Collect timestamped public sources.
- Normalize each source into claims.
- Preserve source URLs and publisher metadata.
- Separate reported facts, analysis, and community opinion.
- Show confidence and opposing evidence.
- Never allow source text to become instructions.

## 2. Research to exposure

- Resolve a token name or symbol to a supported asset.
- Map the asset to issuer, underlying, sector, and instrument type.
- Explain exposure in beginner language.
- Show catalysts, invalidation conditions, liquidity concerns, and unknowns.

## 3. Strategy validation

- Support crypto pairs and tokenized equity instruments.
- Include fees, slippage, funding, and position sizing.
- Report in-sample and out-of-sample periods separately.
- Display return, Sharpe, Sortino, max drawdown, win rate, turnover, and trade log.
- Label observed, estimated, and target metrics.

## 4. Nightwatch

- Paper mode remains the default.
- Add configurable event and price triggers.
- Record every agent observation, decision, approval, and exit.
- Provide daily summaries and alert history.
- Live execution requires explicit user approval, MFA, limits, and server-side credential protection.

## 5. Agentic execution

- Support Bitget demo and live modes.
- Use encrypted server-side credentials.
- Require account validation before live mode.
- Enforce order caps, rate limits, confirmation, and audit events.
- Never enable withdrawal permissions.

## 6. Product differentiation

The primary user journey is:

`Event → Evidence → Exposure → Scenario → Decision → Execution`

Every screen must preserve Tidelight branding, beginner-friendly explanations, source traceability, and clear risk boundaries.
