# Tidelight — S2 产品计划

**产品：** Tidelight，针对代币化美国股票和数字资产的盘后情报终端。
**核心承诺：** 一个经过验证的资产宇宙；对其数据采取行动的三种方式——与人类一起研究、测试阿尔法策略或运行受保护的纸质交易代理。
**北极星用例：** 零售交易者在夜间宏观或公司事件中醒来，查看哪些 Bitget rToken 受到影响，检查引用的证据和反案例，然后选择是否对操作进行纸质测试。如果没有后续的明确选择加入和确定性检查，就无法路由实时订单。

## 黑客马拉松适合

Tidelight 将是一款跨越三个 Bitget 轨道的连贯产品，每个轨道都有单独的、可供法官使用的演示和证据：

| 轨迹 | Tidelight 模式 | 评审证明我们必须出示 |
|---|---|---|
| **人工智能交易台** | 来源主导的活动台：问题 → 捕获的来源 → 验证的声明 → 受影响的资产 → 场景、不确定性和下一个催化剂 | 完成一项真实研究任务的公共可运行演示；证据到主张的链接；任务时间和支持/矛盾覆盖范围 |
| **Alpha Factory** | 盘后策略实验室：Bitget rToken 蜡烛的透明、确定性信号；执行成本和市场会话感知风险 | 可运行策略代码；可重复的**≥60天**回测，样本外期**≥30天**；原始交易、净值曲线、费用/滑点、回撤、Sharpe/Sortino 和胜率 |
| **代理交易** | Nightwatch：用户触发的已完成蜡烛观察者提出有界纸面行动；规则引擎对其进行检查；模拟器记录每个决策并填充 | 可运行蜡烛 → 决策 → 风险检查 → 纸质执行路径；注明日期的审核日志；比赛期间论文运行（目标两周）；拒绝和暂停/恢复测试 |

应用程序必须清楚地标记每种模式并维护单独的指标和工件。该项目不会将相同的通用聊天屏幕描述为三种不同的产品。根据手册，参加多个黑客马拉松主题需要单独的参赛作品和独立的项目；我们应该提交**最强的参赛作品**，除非组织者确认第二个真正独立的交付成果是合适的。

**初始提交建议：** 保持为所有赛道构建产品；目标 **代理交易 → 盘后/事件驱动的纸质代理** 作为其端到端运行程序和可审计纸质日志存在后的主要条目。保持AI Trading Desk作为公共产品最强的人性化工作流程，只有在其样本外记录可再现后才进入Alpha Factory。未经验证的抛光表面并不是一个成功的主张。

## 数据合同和覆盖范围

### Bitget 来源

- `GET /api/v3/market/instruments?category=SPOT`：代码、交易状态、`isRwa` 和 `isReality` 分类。
- `GET /api/v3/market/tickers?category=SPOT`：最后、最高/最低、24 小时变化、交易量/营业额和提供商时间戳。
- `GET /api/v3/reality/market/stock-info`：基础股票、发行人/公司名称、允许的交易时段、周末可交易性。
- `GET /api/v3/reality/market/states`：美国股票交易时间表和 DST 背景。
- 现货蜡烛和公共 WebSocket 股票代码/烛台通道，用于策略历史记录和后续流式传输。遵守 rToken 特定的时间间隔和交易量注意事项。

市场UI是只读的。它使用提供者时间戳，显示过时或不可用的状态，并且永远不会用发明的值填充源中断。工具标志是识别 rToken 的真实来源；符号前缀本身并不能证明。徽标 URL 是表示元数据，永远不会被视为发行者、列表或支持证据。经过验证的发行人域地图可提供已知的公司网站图标；不受支持的 rToken 使用股票标记而不是猜测的加密徽标。完整的长尾配置文件/徽标覆盖是单独缓存的元数据集成。

Bitget 的当前 Reality 指南表示股票代码、工具、烛台和股票参考数据是公开的； Reality 订单簿和平台填写有单独的白名单要求。仅当这些表面实质性地改善了演示时，我们才应该请求 Reality 数据白名单。初始产品不需要帐户凭据即可显示市场数据。

### 持久数据边界

- **Supabase** 保留用户、偏好、观察列表、研究运行、证据、纸质账户/订单、策略定义和回测运行的记录系统。
- 市场报价是提供商快照，而不是个人记录。使用 `provider`、`symbol`、`category`、`as_of` 和 `received_at` 进行归一化；保留足够的原始来源来重现回测。避免使用公共写入端点来引用。
- 公共参考/目录数据对访客来说是只读的。用户组合、关注列表、代理偏好、研究和纸质账本均受 `auth.uid()` RLS 的保护。浏览器变量或公共表中没有 `service_role` 键。
- 不要将真实的交换凭证存储在用户元数据、普通 Postgres 行、GitHub 或浏览器本地存储中。如果需要帐户连接，请使用专用的秘密保管库和严格许可的密钥。

## 系统架构

1. **Next.js / Vercel：** 产品路由、经过身份验证的服务器操作、公共只读 Bitget 代理、仅服务器 Qwen 适配器、运行状况/版本表面。 Supabase `pg_cron` 处理仅数据库的每日应用内摘要；预定的市场检查仍然是一个单独的释放门。
2. **Bitget 适配器：** 类型化 REST/WebSocket 边界；验证信封和小数值；仪器缓存与股票节奏分开；显式超时、重试/退避、模式验证和断路器/不可用状态。
3. **Supabase Postgres + Auth：** 所有者范围内的产品数据和可重现的实验记录。每个公开的表都有 RLS 和显式角色授予。仅使用来自受信任工作人员的服务凭据。
4. **研究引擎：** 源捕获 → 标准化/重复数据删除 → 声明提取 → Qwen 合成仅限于捕获的证据 → 声明/证据验证 → 保存摘要。推论明显与来源事实分开。
5. **策略引擎：** 确定性 TypeScript/Python 独立核心，具有版本化策略配置、蜡烛标准化、费用/滑点模型、训练/测试分割、可重复种子、交易级输出，并且无未来数据泄漏。
6. **代理运行器：**市场/事件触发→上下文快照→策略/Qwen提案→确定性风险门→纸张填充模拟器→审计事件。 Qwen可以提出并解释；它无法绕过硬限制。
7. **可观察性：** 提供者健康状况、上次成功更新、提要年龄、运行 ID、模型/版本、错误类别、成本/延迟和决策理由。切勿记录秘密值或原始凭证。

## 代理安全及纸张执行规则

- 默认模式仅纸质；公共演示中没有帐户连接，也没有实时订单路线。
- 头寸、每日损失、每个交易品种的风险、陈旧供给、最大点差、价格带、重复订单和市场会话规则是确定性的，并在人工智能输出后强制执行。
- 每个提案都包括市场快照、源/证据 ID、模型和策略版本、风险检查、建议的行动、拒绝原因、模拟价格/费用/滑点和用户覆盖。
- 拒绝对陈旧或错误分类仪器的所有操作。当价格缺失或不一致时拒绝执行。揭露原因；不要重试实时操作。
- 实时订单功能是未来的一个里程碑。它需要单独的用户授权、受限的 API 密钥、无提款权限、IP 允许列表、小型大写字母、每个订单确认和终止开关。不要为当前只读里程碑请求 Bitget 交易机密。

## API 所需的密钥和访问权限

### 现在需要

**Bitget 公共现货代码、公共工具/RWA/Reality 标志或 Reality 股票/会话参考不需要新的 API 密钥。** 这些是只读公共端点。已在 Vercel 上配置为 `BITGET_QWEN_API_KEY` 的 Qwen 密钥仍保留在服务器端用于 AI 研究。

### 仅当我们选择这些集成时可选密钥

| 密钥 | 用途 | 现在需要吗？ | 批准后的目的地 |
|---|---|---:|---|
| `POLYGON_API_KEY`（或当前支持的 Massive 等价物） | 用于 rToken 与基础资产比较和另一个市场数据回退的美国本土股票参考蜡烛图 | 否； Bitget rToken蜡烛覆盖初始策略工作 | 仅Vercel加密服务器环境 |
| `FINNHUB_API_KEY` | 更广泛的新闻/公司活动丰富和发行人简介/徽标元数据，适用于 2,800 多个 Reality 列表的长尾 | 初始版本可选； Bitget 已提供价格、Reality 分类、股票代码/名称、会话和周末标志 | 仅 Vercel 加密服务器环境；缓存的服务器端请求 |
| `BITGET_API_KEY`、`BITGET_API_SECRET`、`BITGET_API_PASSPHRASE` | 经过认证的账户数据或真实兑换订单；非公开价格或纸质交易 | **尚未提供** | 仅专用服务器端秘密存储；单独的受限密钥，IP白名单，无提现权限，首先明确的实时交易授权 |
| Supabase 服务/密钥 | 绕过用户 RLS 的可信计划同步或后端服务操作 | 公共馈送路由不需要；当前 Supabase 身份验证连接已仅配置 | 服务器/边缘功能机密；从来没有 `NEXT_PUBLIC_*` |

不要将密钥粘贴到 Tidelight 的公共 UI、问题、提交或普通设置字段中。当需要可选集成时，请在请求之前指定特定密钥、权限范围和加密服务器目标。除非需要集成并且用户已授权目的地，否则切勿将机密传输给提供商。

## 验证记分卡

- **市场完整性：** 工具匹配率、报价新鲜度 p50/p95、API 错误率、rToken 分类检查、缺失标识率。
- **桌面质量：**洞察时间、引文覆盖率、无支持的声明率、矛盾覆盖率、来源多样性。
- **定量：** 总/OOS 回报、夏普、索蒂诺、最大回撤、胜率、营业额、费用、滑点、尾部损失天数、市场时段细分。
- **代理：**提案、接受/拒绝的操作、风险规则违规率（目标 0）、拒绝的陈旧饲料计数、人工接管率、成本后的纸张 P&L、基线增量。
- 报告样本大小、周期、数据源、模型/版本以及每个结果是否是观察、模拟、估计或目标的。切勿发明采用率或绩效数字。
