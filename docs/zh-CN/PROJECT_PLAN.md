# Tidelight · 黑客马拉松构建计划

**赛道覆盖：** AI Trading Desk + Alpha Factory + Agentic Trading。实施了有证据支持的研究、确定性历史策略基线和仅纸质的 Nightwatch 控制界面。下一个构建优先事项是这些工作流程之间的连续性，然后是更强有力的研究和策略验证。产品所有者已确认安全与登录验证完成。请参阅有序的[产品演进路线图](./PRODUCT_EVOLUTION_ROADMAP.md) 和详细的[黑客松产品计划](./HACKATHON_PRODUCT_PLAN.md)。

**目标用户：**持有或关注代币化美国股票并希望在决定是否采取行动之前查看周末或盘后事件的活跃零售交易者。人类交易者做出决定； Tidelight提供可追溯的证据和场景。

**论文：** 代币化股票全天候交易，而其最重要的故事的发布时间却参差不齐。 Tidelight 将事件转化为可供决策的研究笔记，其关键主张可以追溯到来源。

**标语：** 查看会话之间的信号。

## 为什么这个条目

为 AI 交易台轨道构建。差异化的工作流程是从事件到暴露的研究：确定发生了什么变化，将来源事实与推理分开，将事件映射到受影响的公司，显示相反的场景和催化剂，然后保存分析。该产品不会下订单或告诉用户该买什么。

评审故事是具体的前后：用户询问新的出口限制对代币化半导体控股意味着什么； Tidelight 返回带时间戳的证据、曝光图、对比点以及会改变论文的条件。实施了源头限制概要；更广泛的主要来源发现、独立出版商验证和测量的用户任务结果仍然开放。 P0 路线图项目将经过验证的暴露直接与策略回放和论文评审联系起来。

## 用户旅程

1. 开设清晰的盘后市场柜台并选择跟踪股票。
2. 提出事件问题或选择建议的提示。
3. 收集官方发布、备案、信誉良好的报告和可用的只读市场背景。
4.提取权利要求，注明来源URL、出版者、出版时间、检索时间和支持段落。
5. 使用Qwen 仅将捕获的证据合成为事件摘要、公司暴露、反证、情景、不确定性和下一个催化剂。
6. 将摘要保存到用户的 Supabase 工作区；让用户更新他们的观察列表和风险背景。
7. 通过打开声明及其原始来源来演示来源追踪。

## 架构

- **网络：** Next.js 应用路由器、TypeScript、Vercel。
- **身份和存储：** Supabase Auth + Postgres。 RLS 将每个保存的运行、来源、证据项目、监视列表项目和曝光快照的范围限定为登录所有者。
- **研究：**仅服务器提供程序适配器。 Qwen 密钥保留在服务器上。直接 Bitget 公开市场 API 为经过验证的工具和蜡烛视图提供支持；代理中心集成将根据用例进行选择和限制。当前产品中没有账户密钥、交易工具或订单执行。
- **证据：** Postgres 中的标准化来源和声明到来源关系；每个输出都将来源事实与模型推理区分开来。
- **后备：** 如果提供者不可用，则显示明确的不可用状态。切勿将模拟内容或过时的引用呈现为实时数据。

## 演示记分卡

- 最后摘要中的每一个事实主张都链接到来源和支持段落。
- 跟踪声明引用覆盖率、无支持的声明率、矛盾证据覆盖率和研究完成时间。
- 将 Qwen 的简介与小型标记事件集上的人类编写的固定基线进行比较。
- 仅报告观察到的结果；在进行用户测试之前，请制定验证计划而不是发明使用指标。
- 显示数据时间戳并区分实时数据、延迟数据、缓存数据和说明性数据。
- 保持研究和教育框架；不将输出表示为财务建议或交易信号。

## 释放门

- 任何来源、声明、监视列表项或保存的运行都不能跨越用户边界；用 RLS 验证。
- 没有 AI 密钥发送到浏览器或提交到 Git。
- 没有未经验证的股票代码被标记为 Bitget 代币化权益工具。
- 没有样本引用、发明的故事或生成的输出被标记为当前事实。
- 在组织者确认的截止日期前提交并附上所需的 X 帖子链接。
