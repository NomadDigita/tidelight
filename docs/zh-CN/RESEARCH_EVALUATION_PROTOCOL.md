# Tidelight 研究评估协议

## 用途

衡量 Tidelight 是否帮助审阅者从问题转向有根据的、基于来源的注释。这是一个测量计划，而不是结果报告。在审阅者完成以下标签之前，不会要求基准分数。

## 基准设置

从 10-20 个日期公开事件开始，涵盖至少三个发行人或宏观类别。对于每个事件，保留：

- 原始问题和提出问题的时间戳；
- 一份官方来源或备案以及一份独立编辑的出版商来源（如果有）；
- 相关支持段落和任何反证段落；
- 预期受影响的发行人或市场以及人工撰写的简短参考说明；
- 源发布时间、捕获时间、URL 以及页面是否完全可访问。

使用具有明确公共记录的事件。排除谣言、无法独立检查的付费声明以及仅因为它们使模型看起来不错而选择的示例。在对即时修订评分之前冻结事件集。

## 审阅者标签

两名审阅者独立标记每个显示的声明：

1. **报价匹配：** 准确、基本准确或不受支持。
2. **主张必然性：** 支持、矛盾、仅根据上下文或不通过引用成立。
3. **来源适合：** 主要、独立报告、其他已知出版商或用户提供/未经验证。
4. **反证据：** 存在、捕获集中不存在或不适用。
5. **解释边界：** 来源事实、分析师推论或不受支持的断言。

在计算事件分数之前解决分歧。记录初始标签和解决方案，以便及时更改无法消除审阅者的分歧。

## 指标

| 公制 | 定义 |
|---|---|
| 引文覆盖范围 | 显示的具有有效来源和引用的事实声明 ÷ 所有显示的事实声明。 |
| 不支持的主张率 | 标记为不支持或不成立的主张 ÷ 所有显示的事实主张。 |
| 引用保真度 | 引用的段落与捕获的源文本匹配的声明 ÷ 所有显示的事实声明。 |
| 反证据覆盖范围 | 捕获的反对或合格证据出现在简短的事件 ÷ 审阅者在捕获的来源中发现此类证据的事件。 |
| 源多样性 | 每个事件的不同发布者域和源类的数量。域名计数并不能证明编辑独立性。 |
| 任务时间 | 从打开问题到保存已审阅的注释的时间，以中位数和范围报告。 |

报告每个比率的原始分子和分母。细分官方、发布者和用户粘贴的证据。空白反证分母是“未测量的”，不是 0% 或 100%。

## 操作流程

1. 从当前生产提示和支持的源中捕获基线。
2. 根据确切存储的源段落（而不是模型摘要）审查声明。
3. 冻结标签和基线报告。
4. 一次更改一个源或提示行为，然后重新运行相同的案例。
5. 发布聚合指标以及已知限制和至少一个失败案例。

当前实现支持 Mini 中最多三个获取的公共源以及 Pro 中最多五个用户粘贴的段落。获取仅限于选定的发行人 SEC.gov 和精选的发行商白名单。域身份不独立验证；更丰富的源发现和源级基准结果仍然是未来的工作。

## 可重复评分

复制 `docs/benchmarks/research-benchmark-template.json`，将示例替换为冻结事件集，并保留两个独立审阅者标签以及每个索赔的已解决裁决。当来源可访问时，包括准确捕获的段落。评分者拒绝不完整的评论集，并且不会将空分母转换为 0% 分数。

运行它：

```sh
node scripts/score-research-benchmark.mjs path/to/research-benchmark.json
```

JSON 报告包括原始计数、比率、源类总数、不同域/源类平均值、任务时间中位数和范围以及完成门。完整的分数需要来自三个类别的至少 10 个事件、有效的源捕获元数据以及两名审阅者以及对每个显示的声明的裁决。如果基准输入包含未发布的评论注释，请将其保密；仅发布已解决的报告和方法。
